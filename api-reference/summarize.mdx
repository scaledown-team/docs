title: "Summarize"
description: "Produce an abstractive summary of a block of text through the OpenAI-compatible chat completions API."
---

## Overview

Summarize is called through the OpenAI-compatible `POST /v1/chat/completions` endpoint. Set `model` to `summarize` (latest) or `summarize-1` (pinned version) and send the text as the last user message. The model condenses it in its own words without adding new information or commentary. Unlike extractive summarization, the output is a fluent rewrite - not a selection of lifted sentences.

Because the endpoint is OpenAI-compatible, you can point an unmodified OpenAI or OpenRouter SDK at ScaleDown by changing only the base URL and API key.

```
POST https://api.scaledown.xyz/v1/chat/completions
```

## Request

<ParamField body="model" type="string" required>
  `"summarize"` (always the latest version) or `"summarize-1"` (pinned to version 1). Both currently behave identically.
</ParamField>

<ParamField body="messages" type="array" required>
  Standard OpenAI chat messages. The **last user message** is the text to summarize. Any **system** messages are joined and used as the summary `instructions`.
</ParamField>

<ParamField body="max_tokens" type="number" default={200}>
  Standard OpenAI field. Maximum number of tokens in the generated summary. Defaults to `200`, which is also the maximum: larger values are capped at 200, and the model is instructed to finish within the limit. If a summary still hits the limit it is cut off and the parsed result sets `finish_reason` to `"length"` with a `notice`. For a higher output limit, email [neal@scaledown.ai](mailto:neal@scaledown.ai).
</ParamField>

<ParamField body="document" type="string">
  Non-standard extension, passed with the SDK's `extra_body`. A base64-encoded file to summarize. Supported formats: JPEG, PNG, TIFF, single-page PDF, multi-page PDF. The file is processed via AWS Textract OCR and the extracted text is used as input.
</ParamField>

<ParamField body="document_mime_type" type="string">
  Non-standard extension, passed with `extra_body`. MIME type of the document (e.g. `"image/jpeg"`, `"application/pdf"`). Required when `document` is provided.
</ParamField>

<ParamField body="text" type="string">
  Optional top-level override for the input text. When present it takes precedence over the last user message - this lets a [batch](/api-reference/batch-overview) item `body` be reused verbatim. Likewise a top-level `instructions` string takes precedence over system messages.
</ParamField>

Temperature, top-p, and other sampling parameters are fixed and not configurable.

## Response

A standard `chat.completion`. The summary result is a **JSON string** in `choices[0].message.content` - parse it to read the fields below.

<ResponseField name="model" type="string">
  Echoes the `model` you sent (`summarize` or `summarize-1`).
</ResponseField>

<ResponseField name="usage" type="object">
  `prompt_tokens` is the input tokens billed for the request, `completion_tokens` the model's output tokens, and `total_tokens` their sum.
</ResponseField>

<ResponseField name="choices[0].message.content" type="string">
  A JSON string with these fields:

  <Expandable title="Parsed content">
    <ResponseField name="summary" type="string">
      The generated summary text.
    </ResponseField>
    <ResponseField name="input_chars" type="number">
      Character count of the input text.
    </ResponseField>
    <ResponseField name="output_chars" type="number">
      Character count of the generated summary.
    </ResponseField>
    <ResponseField name="latency_ms" type="number">
      End-to-end request latency in milliseconds.
    </ResponseField>
    <ResponseField name="input_tokens" type="number">
      Input tokens billed for the request. Output length is capped at 200 tokens and does not add to the input-token charge.
    </ResponseField>
    <ResponseField name="finish_reason" type="string">
      `"stop"` when the summary finished on its own, or `"length"` when it was cut off at the output limit.
    </ResponseField>
    <ResponseField name="notice" type="string | null">
      Present only when `finish_reason` is `"length"`. Explains that the output limit was reached and that a higher limit is available by contacting neal@scaledown.ai.
    </ResponseField>
    <ResponseField name="ocr_text" type="string | null">
      The raw text extracted from the document via OCR. `null` if no `document` was provided.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error responses

| Status | Meaning |
|--------|---------|
| `400 Bad Request` | No input text (no user message, `text`, or `document`). |
| `402 Payment Required` | Insufficient credits. |
| `422 Unprocessable Entity` | Malformed request body or OCR failed. |
| `500 Internal Server Error` | Inference service unavailable. |
| `504 Gateway Timeout` | Summarization request timed out. |

## Authentication

Include your API key in every request using the `x-api-key` header. `Authorization: Bearer <your-api-key>` is also accepted, so an OpenAI SDK only needs its `api_key` set.

```bash
-H "x-api-key: <your-api-key>"
```

## Examples

### Basic summary

<CodeGroup>

```bash cURL
curl -X POST https://api.scaledown.xyz/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-api-key: <your-api-key>" \
  -d '{
    "model": "summarize",
    "messages": [
      {"role": "user", "content": "Your long text here..."}
    ]
  }'
```

```python Python
import json
from openai import OpenAI

client = OpenAI(
    base_url="https://api.scaledown.xyz/v1",
    api_key="<your-api-key>",
)

r = client.chat.completions.create(
    model="summarize",
    messages=[{"role": "user", "content": "Your long text here..."}],
)
print(json.loads(r.choices[0].message.content)["summary"])
```

```typescript TypeScript
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.scaledown.xyz/v1",
  apiKey: "<your-api-key>",
});

const r = await client.chat.completions.create({
  model: "summarize",
  messages: [{ role: "user", content: "Your long text here..." }],
});
const result = JSON.parse(r.choices[0].message.content!);
console.log(result.summary);
```

</CodeGroup>

### With instructions

Put format, language, focus area, or length guidance in a **system** message. It extends, and does not replace, the default behaviour (no new information, no commentary).

<CodeGroup>

```bash cURL
curl -X POST https://api.scaledown.xyz/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-api-key: <your-api-key>" \
  -d '{
    "model": "summarize-1",
    "max_tokens": 150,
    "messages": [
      {"role": "system", "content": "Use bullet points. Focus on dates and key decisions only."},
      {"role": "user", "content": "Your long text here..."}
    ]
  }'
```

```python Python
r = client.chat.completions.create(
    model="summarize-1",
    max_tokens=150,
    messages=[
        {"role": "system", "content": "Use bullet points. Focus on dates and key decisions only."},
        {"role": "user", "content": "Your long text here..."},
    ],
)
print(json.loads(r.choices[0].message.content)["summary"])
```

```typescript TypeScript
const r = await client.chat.completions.create({
  model: "summarize-1",
  max_tokens: 150,
  messages: [
    { role: "system", content: "Use bullet points. Focus on dates and key decisions only." },
    { role: "user", content: "Your long text here..." },
  ],
});
console.log(JSON.parse(r.choices[0].message.content!).summary);
```

</CodeGroup>

### Summarizing a document

Pass a base64-encoded image or PDF through `extra_body` (`extra_body` fields are merged into the top level of the request). The OCR text is extracted automatically and summarized, and the raw OCR output is returned as `ocr_text`. A message is still required; use a short placeholder user message.

<CodeGroup>

```bash cURL
DOCUMENT=$(base64 -b 0 -i report.pdf)

curl -X POST https://api.scaledown.xyz/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-api-key: <your-api-key>" \
  -d '{
    "model": "summarize",
    "messages": [
      {"role": "system", "content": "Use bullet points. Focus on key figures and decisions only."},
      {"role": "user", "content": "Summarize the attached document."}
    ],
    "document": "'"$DOCUMENT"'",
    "document_mime_type": "application/pdf"
  }'
```

```python Python
import base64

with open("report.pdf", "rb") as f:
    document = base64.b64encode(f.read()).decode()

r = client.chat.completions.create(
    model="summarize",
    messages=[
        {"role": "system", "content": "Use bullet points. Focus on key figures and decisions only."},
        {"role": "user", "content": "Summarize the attached document."},
    ],
    extra_body={"document": document, "document_mime_type": "application/pdf"},
)
print(json.loads(r.choices[0].message.content)["summary"])
```

```typescript TypeScript
import fs from "fs";

const document = fs.readFileSync("report.pdf").toString("base64");

const r = await client.chat.completions.create({
  model: "summarize",
  messages: [
    { role: "system", content: "Use bullet points. Focus on key figures and decisions only." },
    { role: "user", content: "Summarize the attached document." },
  ],
  // @ts-expect-error ScaleDown extension fields
  document,
  document_mime_type: "application/pdf",
});
console.log(JSON.parse(r.choices[0].message.content!).summary);
```

</CodeGroup>

## Notes

- The base instructions (no new information, no commentary) are always applied. System messages add on top of them - they do not replace them.
- `GET /v1/models` lists `summarize` and `summarize-1`. The bare name always points at the latest version; use `summarize-1` to pin.
- Streaming is not supported; the full result is returned in one response.
